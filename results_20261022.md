## 1. Main results

**Table 1: baseline vs our current recipe.**
- *Baseline* is our recipe as of 2026-10-18: center-cropped images, all Gemma layers, a 0.75 s / 0.9 s action window, and 50 RoboTwin demos per task.
- *Now* is the current recipe described in Section 3. On RoboTwin that means 110 demos per task with the original 16-sample window.
- Both are run in adaptive mode: the timing head decides when to query the policy again.
  - Baseline: anywhere in 0.02–0.5 s; on RoboCasa it actually used a median of 0.37 s.
  - Ours: 0.2–0.8 s on RoboCasa, with a median of 0.58 s. On RoboTwin both still use 0.02–0.5 s.
- Each number is the mean success over tasks. RoboCasa: 9 tasks × 50 episodes. RoboTwin: beat_block_hammer, stamp_seal, stack_blocks_three and press_stapler, 100 episodes each.

**Table 2: adaptive vs fixed query timing, same policy.**
- The trained policy is identical in every column (our current recipe); only the execution changes.
- *Adaptive*: the timing head chooses each interval within 0.2–0.8 s.
- *Fixed*: the policy is queried every 0.2 s or every 0.4 s.
- This isolates the benefit of adaptive timing. In Table 1, by contrast, the policy itself changes.

## 3. Recipe

| | Baseline (2026-10-18) | Ours |
|---|---|---|
| VLM | frozen pi0.5 (its image encoder SigLIP-So400m + its language model Gemma-2B), all Gemma layers | frozen pi0.5, **first 6 Gemma layers only** |
| Image input | center crop | **letterbox (pad) the full frame** |
| Action expert | flow matching, 28M parameters, cubic B-spline output | same |
| Action window per query | 16 samples (0.75 s RoboCasa, 0.9 s RoboTwin) | **24 samples (1.15 s) on RoboCasa**; RoboTwin still 16 (24 under test) |
| B-spline control points | 8 | 11 (RoboCasa) |
| Query interval range (timing head) | 0.02–0.5 s | **0.2–0.8 s** (RoboCasa) |
| RoboTwin training data | 50 official demos per task | **110 per task** (50 official + 60 DDA-VLA demos) |
| RoboCasa training data | 404–512 demos per task | same |
| Training | per task: 60k (RoboCasa) / 40k (RoboTwin) action steps + 10k timing steps; batch 32, lr 2e-4 | same |

The window is the trajectory one policy query predicts. The robot executes only its first part, whose length the timing head chooses, and then queries again.

## 4. Conclusion

1. **Longer action windows are what make adaptive timing work.** Raising the window from 0.75 s to 1.15 s and the interval cap from 0.5 s to 0.8 s gave +10.9 points on RoboCasa. Adaptive now clearly beats a fixed 0.4 s interval; before, the two were tied. Retraining only the timing head gave a few points at most.
2. **How the VLM sees the image matters.** Letterboxing instead of center-cropping and reading features from Gemma layer 6 gave +10 points on RoboCasa and roughly tripled RoboTwin success on 50 demos.
3. **More demonstrations is the strongest lever on RoboTwin.** 60 extra demos per task: +18 points on the same episodes.
4. **A bigger action expert does not help.** 28M → 165M gave about +6 points (not significant); 390M gave nothing more.
5. **Other changes tried that don't help on top of the final recipe:**
   - Fine-tuning pi0.5's image encoder (last 4 SigLIP blocks): +0.9 points over 9 tasks, not significant. Also fine-tuning its 6 Gemma layers: −0.5 points on 4 tasks. Both had helped the older, shorter-window recipe.
   - Image augmentation.
   - Combining a bigger expert with augmentation.
